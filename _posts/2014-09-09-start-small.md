---
title: "Start small"
summary: "Two big pieces of work, both approached the same way: start with a small proof of concept and grow it through a series of mini-projects."
date: 2014-09-09
---

I started two large items of work earlier this week.

The first was a discussion around integration tested in an SOA environment.

The second was related to the implementation of a notification system within an angular application.

I fully expect to be working near full time on both of these task for the next 3-4 weeks, and making small changes and enhancements for the foreseeable future.

I have approached both problems by starting small with a proof of concept idea, and will then be looking to add functionality in a series of small min-projects. This will hopefully allow me to build a large scale system, with confidence that the code infrastructure works.

You might ask how I can be confident that something I have yet to finish will be successful. This come from the initial point, which is start small, get that right first. Don’t be afraid to stop and start again is it isn’t working. I would suggest spending significant time upfront understanding the challenge will save time overall.
